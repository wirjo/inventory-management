Catalyst Components — System Architecture

Factory Inventory Management System — Vue 3 SPA + FastAPI backend, in-memory JSON data

System Overview

Frontend

Vue 3 SPA (port 3000)

  • Vite dev server
  • Composition API
  • vue-router (6 views)
  • axios HTTP client (api.js)
  • i18n: en / ja locales
↔
Backend

FastAPI (port 8001)

  • main.py — REST endpoints
  • Pydantic response models
  • Filtering: warehouse, category, status, month
  • CORS: allow all origins
↔
Data

In-memory JSON (no DB)

  • server/data/*.json
  • Loaded once via mock_data.py
  • inventory, orders, demand, backlog, spending, POs

Request / Data Flow

1. User interacts with a view (e.g. sets a filter in FilterBar.vue)
2. Composable useFilters.js updates shared filter state (reactive refs)
3. View calls a method on client/src/api.js (axios → http://localhost:8001/api/...)
4. FastAPI route in main.py applies apply_filters() / filter_by_month() over in-memory lists
5. Pydantic validates the response shape, JSON returned to the client
6. Vue stores raw data in refs (e.g. allOrders, inventoryItems); computed properties derive filtered/aggregated views
7. Template re-renders — KPI cards, tables, charts (custom SVG)

Cross-Cutting Concerns

Filtering

  • 4 filters: Time Period, Warehouse, Category, Order Status
  • Shared via useFilters.js, applied server-side via query params
  • Inventory has no time dimension — month filter not applicable

i18n

  • useI18n.js composable + locales/en.js, ja.js
  • LanguageSwitcher.vue toggles locale
  • Nav labels use t('nav.*') — except Reports (hardcoded string)

Auth

  • useAuth.js — mock profile (John Doe)
  • No real authentication (demo app)
